# Patch Notes - st (suckless terminal) custom build

**Timestamp:** 2026-07-06 11:33:20-04:00

The following modifications and bug fixes were applied to this build:

## 1. Concurrency & Safety Fixes
*   **Safe Child Process Exit (`newterm`):** Fixed a critical vulnerability in `newterm` where a failure to execute the child binary (`st` via `execlp`) would allow the child process to fall through to the main terminal thread and execute a duplicate main event loop. Added `_exit(1)` on execution failure.
*   **Async-Signal-Safe Reloading:** Redefined the live-reload mechanism (`SIGUSR1`). Instead of executing non-async-signal-safe routines (like font unloading, X11 clearing, and drawing) directly inside the signal handler context, a `volatile sig_atomic_t` flag is set. The actual reload is deferred and executed safely at the start of the next main event loop cycle.

## 2. Resource Leak & Memory Corruption Fixes
*   **Zombie Process Reaper:** Refactored the `sigchld` handler to loop over `waitpid(-1, &stat, WNOHANG)` to reap all exited children. This successfully prevents zombie process accumulation when executing helper programs (e.g. `externalpipe` and `newterm`).
*   **XResources String Pointer Memory Corruption:** Adding `XCloseDisplay(dpy)` at the end of `xrdb_load()` previously closed the display connection but left `termname` and the `colorname[]` array pointing to memory that was freed upon display termination. This caused `$TERM` to be set to a garbage pointer, breaking Neovim colors and causing it to fall back to monochrome/dumb mode. Fixed by allocating permanent heap memory for all loaded resource strings using `xstrdup()`.

## 3. HarfBuzz Ligatures Rendering & Animation Fixes
*   **Prevent Out-Of-Bounds Heap Reads & Screen Corruption:** In `hb.c`'s `hbtransformsegment()`, the loop copying shaped codepoints assumed that the output glyph count returned by `hb_shape()` matches the input character sequence length. When ligatures are formed, the output glyph count is strictly smaller. This caused out-of-bounds heap reads of garbage memory, resulting in text corruption, character shifting, overlapping, and chopped-off letters during updates. Fixed by tracking the exact output glyph count and populating trailing ligature cells with a cached, font-specific space glyph index (safely generated on the fly or cached during font loading).
*   **Ligature Flag Management (`ATTR_LIGA`):** Modified the segment mapping in `hb.c` to properly clear the `ATTR_LIGA` attribute from glyphs when a ligature is broken (e.g., during animations or text edits), preventing stale ligature states.

## 4. Selection Auto-Scrolling
*   **Auto-Scroll on Mouse Drag:** Added functionality to scroll the history buffer when selecting text. If selection is active and the mouse is dragged above the top of the terminal window or below the bottom of it, `st` will invoke `kscrollup()` or `kscrolldown()` to dynamically adjust the viewport and extend the selection.

## 5. OSC Color Query Support
*   **OSC 10/11/12 & OSC 4 Query Responses:** Added support for query escape sequences. When an application (like Neovim) queries foreground, background, cursor, or palette index colors using `?` (e.g. `\033]11;?\007`), the terminal now retrieves the RGB values from Xft cache and responds with the current color. This ensures accurate background detection and color schemes.

## 6. DSR 5 Response Support
*   **DSR 5 status query:** Added support for responding to Device Status Report status queries (`CSI 5 n`). The terminal now correctly responds with `CSI 0 n` (Device OK). This satisfies Neovim's startup checks (which send `OSC 11` + `DSR 5` in sequence and wait for the `CSI 0 n` response), resolving the `E1568` startup delay and warning message.

## 7. DECRQM (DEC Private Mode Query) Support
*   **DECRQM Query Responses:** Implemented Request DEC Private Mode (DECRQM) responses for `CSI ? Pm $ p` sequences in `csihandle()`. When queried for private modes like `?2031` (theme sync), `?2026` (synchronized updates), `?2027` (unicode), `?2048` (modes), and `?69` (margins), the terminal now immediately responds with `CSI ? Pm ; 0 $ y` (not supported). This eliminates Neovim startup timeouts, suppresses `E1568: Terminal did not respond to DSR request for 'background' color` warning, and cleans up standard error logs.

## 8. Silenced Unknown CSI Sequences
*   **Silence Parser Warning Spam:** Modified the parser (`csiparse()`) to recognize and ignore colon-separated subparameters (resolving undercurl sequences like `CSI 4:3m`) and allow private markers like `>` (resolving keyboard reporting sequences like `CSI > 4;2m` which are ignored). Also added `case 't':` in `csihandle()` to silently ignore window manipulation commands (e.g. `CSI 22;0;0t`). This completely silences stderr warning spam when launching Neovim.

## 9. Code & Build Cleanups
*   **Dangling Vim Mode Removal:** Deleted `normalMode.c` and `normalMode.h` from the directory, as they were not compiled, linked, or integrated with the main codebase.
*   **Compiler Warning Cleanups:** Wrapped the nested conditional blocks in `mousereport()` inside explicit braces to resolve compiler warnings regarding dangling `else` statements. Added the `xrdb_load()` function prototype at the top of `x.c` to prevent implicit declaration compilation errors.
